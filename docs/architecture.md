# 架构

一次翻译从鼠标事件开始，到浮层上出现译文结束。这份文档按这条路径把代码串一遍，
说清楚每一层负责什么、不负责什么，以及为什么这么切。

```
CGEventTap ─▶ trigger/reducer ─▶ mouse/listener ─▶ lib.rs 的 pipeline
                                                       │
                                        capture/ ──────┤（取文字和位置）
                                                       │
                                        translate/ ────┤（出译文）
                                                       │
                                        trigger/panel ─┘（决定浮层放哪、什么时候收）
                                                       │
                                                  macos/panel（真正的 NSPanel）
```

## 为什么这样分层

**判定的逻辑必须能测。** `trigger/reducer.rs` 是一台纯状态机：输入是普通的结构体，
时钟是参数，输出是「这次事件意味着什么」。它之所以被单独拎出来，是因为
CGEventTap 的回调跑在一个 macOS 嫌慢就会掐断的线程上，而且没有活人会话就跑不起来——
把「拖拽要超过 8px 且 80ms」这种规则写在里面，等于放弃测试。现在这里有二十多个测试，
覆盖阈值、阈值之间的先后关系，以及那些以前只能靠猜的情况（双击、三连击、拖拽之后紧跟的一次点击）。

**取词的策略必须能讲清理由。** `capture/` 只回答一个问题：这次能不能读到选中的文字，
读到了什么，位置在哪。顺序是先问辅助功能接口（直接读，不碰剪贴板、不合成按键），
读不到再考虑要不要 `⌘C`。要不要回退是个**穷举 match**（`should_fall_back_to_pasteboard`），
所以以后新增一种失败原因，不补上这个判断就编译不过。

**浮层的位置是一场状态机。** `trigger/panel.rs` 是纯数据：现在显示的是小圆点还是卡片、
放在哪、用户点过没有、这次的结果属于哪一代。所有窗口操作都由它算出来的
`Transition` 描述，`macos/panel.rs` 负责照做。窗口贴不贴边、放不下往哪翻、
内容多高——这些都能在不开窗口的情况下测。

## 各层职责

| 位置 | 负责 | 不负责 |
| --- | --- | --- |
| `trigger/reducer.rs` | 一次鼠标事件是否该触发翻译，或让浮层收起 | 不知道浮层是否存在 |
| `trigger/panel.rs` | 浮层处于什么状态、放在哪、哪一代 | 不碰窗口 |
| `trigger/placement.rs` | 贴边翻转的几何计算 | 不知道是谁在用它 |
| `mouse/listener.rs` | CGEventTap 的生命周期、权限、把事件翻译成 `PointerEvent` | 不做任何判断 |
| `capture/` | 取到选中的文字和它在屏幕上的位置 | 不决定要不要翻译 |
| `macos/ax.rs` | 辅助功能接口的裸调用，把 `AXError` 分类 | 不决定回退 |
| `macos/panel.rs` | 把 Tauri 窗口变成一个真正的 `NSPanel` | 不知道浮层该在哪 |
| `translate/` | 四家服务共用一个 HTTP 层，各自只写请求和解析 | 不认识鼠标 |
| `lib.rs` | 把上面这些按顺序接起来，管住并发闸门 | 不含业务规则 |

## 一次翻译的路径

### 中键 / 快捷键

1. `reducer` 在**按下**时就判定为 `Trigger`（不等松开）。
2. 管线先抢并发闸门 `PipelineGate`，抢不到就跳过——这保证同时只有一次取词，
   而取词会短暂接管剪贴板。
3. 先显示卡片（加载态），再取词。取词最慢要走一次合成的 ⌘C，没有加载态的话，
   失败看起来和「应用没理我」一模一样。
4. 翻译，写历史，发 `translation-ready`。

### 划词

1. `reducer` 在**松开**时判定：位移 ≥ 8px 且按住 ≥ 80ms，视为拖选；
   位移 < 8px 且与上一次点击在 400ms 内、6px 以内，视为双击选词。
   两者都算 `MouseSelection`。
2. 管线取词，但**不允许走剪贴板回退**。这一步只是为了决定「要不要给一个触发点」，
   为了这个去合成一次 ⌘C，等于在用户还没要求翻译时就动了他的剪贴板。
3. 取到文字 → `trigger/panel` 计算小圆点的位置（优先用辅助功能给的选区矩形，
   拿不到就用鼠标位置），显示，然后**结束**。此时一次请求都没发出去。
4. 用户点小圆点 → `expand_trigger_panel` 命令 → 展开成卡片，这时才真正翻译。
   这一次允许走剪贴板回退：用户已经明确要求了。
5. 收起的几种情况：滚动超过 80 点、点到小圆点之外、Esc、4 秒没被点。

第 5 条里的「点到小圆点之外」有个坑：事件监听器**先于**面板自己的点击处理看到这次点击。
如果「有点击就收起」，小圆点会在被点中的瞬间消失。所以 reducer 只报告「发生了一次点击」，
由掌握小圆点位置的面板决定这次点击算不算数。

## 并发与边界

- **`PipelineGate`** 保证一次只有一次翻译在跑。持有者超时（90 秒）会被强行收回，
  并把这件事写进诊断——否则一次卡死会让应用从此静默忽略所有触发。
- **辅助功能读取**有两道边界：`AXUIElementSetMessagingTimeout`（2 秒，管住 FFI）
  和 `tokio::time::timeout`（3 秒，管住整个读取任务）。
- **剪贴板**在取词期间被接管，但无论从哪条路径退出——包括 panic——都会被完整还原，
  靠的是 `RestoreOnDrop` 而不是在每个 return 前面写一遍还原代码。
- **HTTP** 有连接和总时长超时；非 JSON 的响应体只被「描述」（字节数 + 哈希），
  不会被原样回显到界面上。

## 前端

- `src/api/types.ts` 由 Rust 结构体生成（ts-rs），**不要手写**。CI 会校验它没有漂移。
- `src/store.ts` 是设置窗口里的共享状态；`src/tabs/` 是四个页面；
  `src/ui/` 是基础控件。
- 颜色只在一处定义：`src/styles/globals.css` 里按主题声明 CSS 变量，
  再用 Tailwind v4 的 `@theme inline` 变成工具类。所以组件里写
  `bg-surface text-ink`，明暗切换不需要任何 `dark:`。
- 浮层（`src/components/`）和中键翻译共用一扇窗口：小圆点是「用户还什么都没要求」的样子，
  卡片是「要求过了」的样子。

## 两个刻意的取舍

**只做 macOS。** `lib.rs` 顶部有一句 `compile_error!`，在别的平台上直接编译不过。
以前有一堆 `#[cfg(target_os = ...)]` 分支，没有一个在真实平台上被编译过，更别说运行。

**浮层必须是真的 `NSPanel`。** Tauri 的窗口是普通 `NSWindow`，它做不到两件这里必须做到的事：
点击时不激活本应用（一旦激活，正在读的那个应用会失去焦点，选区往往就没了），
以及不吞掉第一次点击（AppKit 会丢掉非活跃窗口上的首次点击，那就成了「点了没反应」）。
`macos/panel.rs` 顶部写了这段来历；转换失败时应用照常运行，只是退回普通窗口。
